あなたは実装判断を行う Codex または Claude です。
以下の条件で、MarkItDown の導入可否を判断し、採用する場合は最適実装を提案してください。

# 前提
- 目的は、PDF / Word / Excel / PowerPoint / 画像 / ZIP を Markdown に変換し、RAG前処理品質を向上させること
- Windows 11 + WSL2 + Docker Desktop を併用
- 既存候補には Paperless, OCR, Docling, Qdrant, embedding server, OpenClaw 系がある
- MarkItDown を必ず採用する必要はない
- 採用しない判断でもよい
- ただし、採用/不採用の理由は具体的に示すこと

# 判定観点
1. 既存 ingest パイプラインとの整合
2. 日本語文書への適性
3. 変換品質（見出し / 表 / 箇条書き）
4. Docker 化のしやすさ
5. ログ取得のしやすさ
6. 失敗時のリトライ設計
7. OCR / Docling / VLM との責務分離
8. 運用保守性
9. コスト
10. PoC の進めやすさ

# 必須アウトプット
- 採用 / 条件付き採用 / 不採用 のいずれか
- 理由
- 推奨アーキテクチャ
- 実装順序
- 最小PoC設計
- ログ設計
- 想定リスク
- 代替案（不採用または部分採用の場合）

# 制約
- 受け取り手がすぐ着手できるよう、曖昧表現を避ける
- 過剰実装を避ける
- ただし本番導入を見据えた現実的提案を行う
- 日本語ファイル名や Windows 運用上の文字化け・パス問題にも触れること
