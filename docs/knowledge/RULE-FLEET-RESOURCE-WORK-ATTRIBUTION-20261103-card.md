User-authorized operating rule. Recorded 2026-11-03T07:15:30.258351+09:00, Asia/Tokyo.

When reporting CPU/RAM for a computer, also report the concrete work being performed. Required fields: host identity; observation time/timezone and source; physical/logical cores and CPU sample interval/denominator; DIMM installed vs OS-visible/available RAM and separate guest memory; job/project and case/input/output identity; PID, parent/launcher/task/queue, account and known human owner (UNKNOWN when unverified); solver/application, threads/MPI, per-process interval CPU, resident working set and private commit; latest numerical progress/output timestamp, checkpoint/resume status and competing reservations.
A running process or increasing CPU time proves activity, not numerical progress or useful work. Report confirmed progress separately from active/unknown/stale progress. Do not call a stalled-looking log a hang without evidence. Private commit is not physical RAM residency; sums of working sets may double-count shared pages. Never infer headroom from aggregate CPU alone.
Retrieve previous incidents and canonical connection methods first, then refresh live evidence. Exclude hosts explicitly excluded by user (currently Vivobook). Preserve unrelated work; no stop/restart/delete/reuse without exact applicable authorization. Do not expose credentials or unrelated raw engineering data in shared cards. Public cards use only procedure and minimal sanitized facts.
