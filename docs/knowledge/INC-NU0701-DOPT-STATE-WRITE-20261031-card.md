# Durable state pointers must not terminate checkpointed work
INC-NU0701-DOPT-STATE-WRITE-20261031; observed2026-10-31 JST. A Windows Access denied exception during temporary-to-current JSON replacement propagated through a worker future and terminated a finite calculation coordinator. Live process checks distinguished the stopped coordinator from historical state files. Completed native results/checkpoints remained intact. The external source of denial is UNKNOWN; an open deny-delete reader is a possible mechanism, not a diagnosed actor.

Preserved the original coordinator/state/error/event evidence and hashes. Reconciled every existing native result before recovery; only unstarted case IDs were eligible. A new coordinator preserves original ownership and deadline records. Durable state now uses new immutable payloads plus SHA/size commits, while convenience pointer replacement has bounded retries and nonfatal fallback. Readers can verify the latest committed payload independently of a stale convenience file. No unrelated job cleanup, security/ACL changes, reboot or native-solver/input mutation.

Actual Windows deny-delete-handle fault injection on an owned synthetic file verified that the old pointer survived, the new committed state remained retrievable, the writer returned without terminating the coordinator, and pointer update succeeded after handle release. New live child processes and current native checkpoints were verified after recovery. Independent analysis guards also passed through the new persistence. Disk-full/new-file creation failures and the original denial actor remain unresolved risks; tests are not universal fault guarantees.

FMEA/FTA/QC/Control Plan drafts link the same incident and restricted evidence. Detection requires actual processes/checkpoints, not stale JSON or returned PIDs. Recovery requires source/runtime/native-state integrity and exact case reconciliation, never blind replay. Ratings and formal owners unassessed. Sharing-mode semantics reference: [Microsoft CreateFile documentation](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea); this reference does not establish the actual incident cause.
