# トークン節約・セッション運用プロトコル
> Clawstack Unified / 制定: 2026-04-17 / 改訂: 2026-04-29

---

## 1. なぜトークンが無駄になるか

| 原因 | 影響 |
|---|---|
| 長いセッションを引っ張り続ける | 過去会話を毎ターン再読 → コスト指数増 |
| 「全体を見て直して」と丸投げ | AIが広範ファイルを探索 → 無駄読み |
| 重いモデルに何でもさせる | Gemini課金が軽タスクに発生 |
| CLAUDE.md に細則を書きすぎる | 毎セッション起動時読み込みが重くなる |

---

## 2. セッション種別（現実に合わせた3分類）

### A. 開発セッション（新機能・バグ修正）

```
[Plan] → [実装] → [レビュー]
```

- 原則として機能単位で区切る
- フェーズが変わったら新セッションを推奨
- 設計・実装・レビューを1セッションに詰めない

### B. 運用セッション（監視・トラブル対応）

```
[長時間ジョブ監視] + [発生した問題への対応] + [ログ確認]
```

- バックグラウンドタスク通知が複数テーマを横断するため、**1テーマ1セッション**が現実的
- 「OpenRadioss + IATF動画監視」のように並走ジョブを1セッションで扱う
- 問題解決後は trouble_history.md に記録して次セッションへ引き継ぐ

### C. 調査・質問セッション

- 1往復で完結させる
- `local_fast` を使う

## 3. モデル振り分けルール

| タスク種別 | 使うモデル | コスト |
|---|---|---|
| ファイル確認・要約・軽い検索 | `local_fast` (qwen3:8b) | 無料 |
| 差分生成・一括置換・定型実装 | `codex` (qwen3:8b) | 無料 |
| バグ修正・デバッグ・編集 | `google/gemini-2.5-flash` | 課金 |
| 設計・根本原因・方針決定 | `google/gemini-2.5-flash` + Plan先行 | 課金 |

## 4. 開発セッションの手順（新機能・修正時のみ）

### タスク定義

```
目的:
対象ファイル:
変更禁止範囲:
成功条件:
```

### Plan 要求

```
まだコードは書かないでください。Plan のみ作成してください。
目的 / 対象ファイル / 制約 / 期待出力（手順・影響範囲・リスク）
```

### 実装

```
以下の範囲だけ修正してください。対象ファイル以外は変更しないでください。
```

### 終了時の外部化

```
変更ファイル / 変更内容 / 未解決事項 / 次回推奨アクション
→ trouble_history.md または MEMORY.md に保存
```

---

## 5. セッション切替タイミング

| 切替トリガー | 対応 |
|---|---|
| 対象テーマが変わった | 新セッション |
| 設計 → 実装へ移行（開発セッション） | 新セッション推奨 |
| 会話が長くなり前提が重い | `/compact` または新セッション |
| エラーが解決せず3回失敗 | 新セッション（問題を外部化してから） |
| 長時間ジョブが完了した | 結果を記録して新セッションでも可 |

---

## 6. 長期記憶の外部化先

| 種別 | 保存先 |
|---|---|
| 障害・ヒヤリハット | `data/workspace/memory/trouble_history.md` |
| 操作ルール・設計判断 | `~/.claude/projects/*/memory/MEMORY.md` |
| 構造化知識・規格文書 | Qdrant `universal_knowledge` (RAG) |
| 繰り返しルール・制約 | CLAUDE.md（60行以下を維持） |

---

## 7. よくある損失パターン

| パターン | 対策 |
|---|---|
| 「なんか変なので全体を見て直して」 | 対象ファイルと関数を明示する |
| Gemini で「ファイル一覧教えて」を繰り返す | `local_fast`（無料）を使う |
| 同じセッションでエラーを何度も再試行する | 3回失敗したら新セッション＋問題整理 |
| 監視中に別タスクが発生してセッションが肥大化 | 運用セッションとして許容し、終了時に記録する |
