# トークン節約・セッション運用プロトコル
> Clawstack Unified / 制定: 2026-04-17

---

## 1. なぜトークンが無駄になるか

| 原因 | 影響 |
|---|---|
| 長いセッションを引っ張り続ける | 過去会話を毎ターン再読 → コスト指数増 |
| 「全体を見て直して」と丸投げ | AIが広範ファイルを探索 → 無駄読み |
| 重いモデルに何でもさせる | Gemini課金が軽タスクに発生 |
| CLAUDE.md に細則を書きすぎる | 毎セッション起動時読み込みが重くなる |
| 設計・実装・レビューを1セッションに詰める | 文脈肥大 + 手戻り多発 |

---

## 2. セッション設計の基本

```
[Plan セッション]  →  [実装セッション]  →  [レビュー セッション]
  重モデル               軽/中モデル           軽モデル or Codex
```

- セッションはタスク単位で切る
- 対象機能・フェーズが変わったら新しいセッションを開く
- `/clear` は「前提が重くなった」時だけ使う（使う前にメモを外部化する）
- `/compact` は「同タスクを続けたいが会話が肥大した」時に使う

## 3. モデル振り分けルール

`data/workspace/model_router.py` で自動分類可能。

| タスク種別 | 使うモデル | コスト | 備考 |
|---|---|---|---|
| ファイル確認・要約・軽い検索 | `local_fast` (qwen3:8b) | 無料 | Ollama ローカル |
| 差分生成・一括置換・定型実装 | `codex` (qwen3:8b) | 無料 | Ollama ローカル |
| バグ修正・デバッグ・編集 | `google/gemini-2.5-flash` | 課金 | 中タスク標準 |
| 設計・根本原因・方針決定 | `google/gemini-2.5-flash` + **Plan先行** | 課金 | 実装前に計画確認 |

```bash
# CLI で分類確認
python data/workspace/model_router.py "このバグを直して"

# デモ
python data/workspace/model_router.py --demo
```

## 4. 標準作業手順

### Step 1. タスク定義（人間側で整理）
```
目的:
対象ファイル:
対象関数/クラス:
変更禁止範囲:
成功条件:
```

### Step 2. Plan 要求（コードを書かせない）
```
まだコードは書かないでください。
以下のタスクについて Plan のみ作成してください。

目的: [目的]
対象ファイル: [パス]
対象関数: [関数名]
制約: [制約]

期待出力:
- 読むべき範囲
- 実施手順
- 影響範囲
- リスク
- 完了条件
```

### Step 3. Plan 確認チェックリスト
- [ ] 余計なファイルを読もうとしていないか
- [ ] 作業範囲が広がりすぎていないか
- [ ] 変更禁止範囲を侵していないか
- [ ] リスクが許容範囲内か

### Step 4. 実装（範囲限定）
```
以下の範囲だけ修正してください。
対象ファイル以外は変更しないでください。

対象ファイル: [パス]
対象関数: [関数名]
修正内容: [内容]
変更禁止: [禁止事項]
```

### Step 5. 差分レビュー
```
以下の差分をレビューしてください。実装は不要です。

観点:
- バグ混入
- 仕様逸脱
- 境界値漏れ
- 変更範囲の過大化
```

### Step 6. 終了時要約 → RAG or trouble_history へ保存
```
作業完了要約:
- 変更したファイル:
- 変更した内容:
- 変更しなかったもの:
- 想定される影響:
- 未解決事項:
- 次回の推奨アクション:
```

## 5. Claude Code / OpenClaw 向けセッション切替タイミング

| 切替トリガー | 対応 |
|---|---|
| 対象機能が変わった | 新セッション |
| 設計 → 実装へ移行 | 新セッション（Planをメモに残してから） |
| 実装 → レビューへ移行 | 新セッション または `/clear` |
| 会話が長くなり前提が重い | `/compact` または新セッション |
| エラーが解決せず袋小路 | 新セッション（問題を外部化してから） |

## 6. 長期記憶の外部化先

| 種別 | 保存先 |
|---|---|
| 完了サマリ・設計判断 | `data/workspace/memory/trouble_history.md` |
| 構造化知識・規格文書 | Qdrant `universal_knowledge` (RAG) |
| 会話中の一時メモ | セッション内の TodoWrite |
| 繰り返しルール・制約 | CLAUDE.md (最小化を維持) |
| プロジェクト横断情報 | `~/.claude/projects/*/memory/MEMORY.md` |

---

## 7. 禁止事項チェックリスト

- [ ] 曖昧な丸投げ（「なんか変なので全体を見て直して」）をしていないか
- [ ] 重いモデルに単純作業（ファイル確認など）をさせていないか
- [ ] 1セッションで設計・実装・レビューを全部やらせていないか
- [ ] CLAUDE.md を肥大化させていないか（目安: 60行以下）
- [ ] セッション終了時に要約を外部化しているか

## 8. よくある損失パターンと対策

### パターン A: 「なんか不具合があるので全体を見て直して」
→ AIが全ファイルを広く探索。**対策: 対象ファイルと関数を明示する**

### パターン B: 設計・実装・デバッグを1セッションで完結しようとする
→ 会話が肥大化し再読コストが指数増。**対策: フェーズごとに新セッション**

### パターン C: エラーが出るたびに同じセッションで再試行する
→ 失敗の文脈が蓄積する。**対策: 3回失敗したら新セッションで問題を整理し直す**

### パターン D: Gemini で「ファイル名確認して」「一覧教えて」を繰り返す
→ API課金が軽タスクに発生。**対策: `local_fast` (無料) を使う**
