## 4.6 3D-MPM 評価を試行・中断（2026-08-16・ユーザー承認済み）

### 4.6.1 訂正（2026-08-16・ユーザー指摘で発覚）— 爆発の一部は実装バグだった

ユーザーから「旧 4mm×4mm モデルでは爆発していないように見えた」と指摘を受け、
実際に旧 `4mmx4mm_ASSY_20260104.inp`（`scripts/build_4mm_mpm.py` で新規実装）で
再検証した。**「一様グリッドMPMはこの規模では必ず発散する」という上記の結論は
不正確だった。** 見つけた事実:

1. **ドメインが小さい分、同一セル数予算で dx を約4倍細かくできる**（60µm→16µm相当。
   実測では Z 方向の計算コストが不利に働き dx=30µm に落ち着いたが、それでも
   工具角 R0.22 は 7.3 セル、丸穴 φ0.56mm は 18.7 セルと、新モデル dx=60µm 時
   （角 3.7 セル）より明確に改善した）
2. **実装バグ①**: ストリッパー閉じ量を新モデルの値 `0.19mm` のまま流用しており、
   実際の幾何すきま `0.1285mm` より 61.5µm 過剰に押し込んでいた
3. **実装バグ②**: ストリッパー速度を「一定→瞬時に0」という不連続関数にしており、
   閉止完了の瞬間に速度不連続（急制動）を注入していた

両方を修正（すきまは幾何から実測・速度は両端ゼロの smoothstep へ）すると、
爆発タイミングが t=0.07ms→t=0.085〜0.101ms へ遅延し、速度の立ち上がりも
0.87→2.52→18.5→30m/s と緩やかになった。**それでも最終的には同じ速度クランプ
(30m/s) に飽和し、根本的な発散は解消しなかった。**

解像度は明確に改善していたにも関わらず最終的に発散したことから、残る真因は
**解像度不足というより、剛体境界条件（速度の瞬間上書き方式）自体の数値的脆弱性**
である可能性が高い。ペナルティ法・陰的接触など別の接触定式化を試す余地はあるが、
これは新たな実装が必要でセッション規模を超える。

**⚠ 同種の問題を一様グリッドMPMで評価する前に**:
- 剛体工具の速度指令は必ず両端（開始・停止）で速度ゼロとなる滑らかな関数
  （smoothstep等）にする。瞬間停止・瞬間発進は爆発の直接原因になる
- 工具すきま等の幾何依存パラメータは、**そのモデル自身の幾何から実測する**。
  別モデルの既知値を流用しない（本件の実装バグ①の教訓）
- 上記を守っても発散する場合は、速度Dirichlet型の剛体境界条件自体を疑うこと
  （本件で最終的に到達した結論）

## 4. 現在の解析状態 — slice3D で打ち抜きが成立した

3D フル模型では輪郭破断が 9% で頭打ちだったため、**切断線断面の1要素厚 3D スライス**へ移行した
（08-11 §6 の推奨1を実行）。ビルダ: `scripts/build_inc188_slice3d.py`。

### モデル定数

| 定数 | 値 | 意味 |
|---|---|---|
| `THICKNESS` | 0.51e-3 m | 板厚 |
| `DEFAULT_SHEAR_ELEM` | 10 µm | せん断帯の要素寸法 |
| `DEFAULT_CLEARANCE` | 40 µm | ダイ隙間（板厚の約7.8%）。**ゼロだと剪断帯が立たない** |
| `TOOL_GAP` | 5 µm | 工具-板の初期すきま（初期貫入エラー回避） |
| `DEFAULT_GAP_MAX` | 15 µm | 接触ギャップ上限。**TOOL_GAP < Gap_max < CLEARANCE** を必ず満たすこと |
| `DEFAULT_STFAC` | 1.0 | 接触剛性。AC の 0.05 は 10µm メッシュに柔らかすぎた |
| `DEFAULT_NSTEP` | 10 | 破断応力を落とすサイクル数。Altair 既定。**0 は爆発する** |
| `DEFAULT_SLICE` | 20 µm | X方向スライス厚（1要素） |

### S1 → S5 の履歴

| Trial | 変更 | 結果 |
|---|---|---|
| S1 | TYPE7 接触 | NORMAL TERMINATION / 1.58M cycle だが **削除0**。塑性ひずみ全要素 0.0、Von Mises 最大 12.61 Pa。パンチが板をすり抜けた。真因は破壊則ではなく **接触ギャップ0**（TYPE7 の Gap_scale/Gap_max/GAPmin/Igap すべて0、ソリッドは板厚を持たないので接触が起動しない） |
| S2–S4 | TYPE25 移植・接触ギャップ付与 | 荷重は立つが曲げで切れる |
| **S5** | **y=0 対称拘束 + TYPE25 + Stfac=1.0 + Nstep=10** | **NORMAL TERMINATION / 1,756,501 cycle / 破断 51 要素 = 0.51mm ÷ 10µm = 板厚貫通クラック1本。成立。** |

S5 のエネルギー収支: 閉じ率 97.1%（PLASTIC 90.3% / CONTACT 3.9% / KINETIC 0.7% / INTERNAL 2.2% / HOURGLASS 1.8e-36）。
断面プロットでスラグが平行に降下し、ストリップが z=0–0.51mm に留まることを確認済み。

**ソルバの ERR = -97.0% は物理エラーではない。** `(I+K-W)/W` が塑性散逸を含まないため、
塑性が支配的なモデルでは構造的に負に出る。ERR で合否を判定しないこと（08-11 §4 と同旨）。

### 直前の真因2件（再発させない）

1. **接触ギャップ0** → ソリッド要素では接触が起動せず、荷重ゼロのまま工具が貫通する（S1）
2. **y=0 の対称拘束欠落** → 板が剪断でなく曲げで切れる（commit `1fde82f0`）

### ⚠ 校正不足がそのまま出ている

ピーク荷重が**進入量 9%** で立つ。アルミの一般帯は 20–40% で、S5 の約13%と同じ症状。

**この 1,230 N を実荷重として扱わないこと。** bd `n47u` の校正後に再実行して初めて定量値になる。

### ⚠ この解析で「言ってよいこと / 言ってはいけないこと」

要素 100µm は板厚方向 5 層しかない。文献のせん断帯は 21–44µm なので**解像できていない**。

- 言ってよい: 荷重レベル、ストリッパー押さえの成立、4 パンチの時間差と相互作用、スラグの分離挙動、境界条件と接触設定の妥当性
- **言ってはいけない**: せん断面・破断面の形状、バリ・だれ・かえり、破断開始位置の定量予測

破断面が要る場合は slice3d 経路（10µm）を使うこと。全体を 10µm で切ると約 5.7 億要素で不可能。

### 既知の割り切り（次回改善候補）

1. パンチ – ダイ / パンチ – ストリッパー間の接触は定義していない。アパーチャが揃っている前提で、
   揃っていない場合は工具同士がすり抜ける（材料の挙動には影響しない）
2. 材料の 5 片融合時、OCC が向きの反転した重複ソリッドを残す。`removeAllDuplicates` 後は
   1 領域として正しく張られる（メッシュ積算体積 95.3239 mm³ で検証済み）。
   ここで負体積ソリッドを `remove` するとカーネルが "Could not fix wire" で落ちる
3. `occ.translate` は融合後ソリッドで同じく落ちる。Z シフトはメッシュ座標へ加算して回避している
4. **孤立節点（P1 で踏んだ罠。修正済み）**: `remove(recursive=False)` は削除ソリッドの面・辺を
   残すため `generate(3)` がそれらを 2D メッシュし、四面体に属さない節点を作る。P1 では
   全 282,412 節点の **58.2% が孤立**し、GRNOD まで汚染された（パンチ群 27,852 中 23,510 が孤立）。
   `recursive=True` は共有面ごと消してブランクを壊すので使えない。四面体が参照する節点だけを
   残すこと。**Starter は 0 ERROR / 0 WARNING で素通りする**ので、初期フレームの座標範囲を
   自分で検算すること（P1 は Z 最小 -0.095mm で発覚した）。
   なお孤立節点は質量ゼロ・要素なし・接触面外なので**解析結果は汚染しない**。
   除去による高速化も実証されていない（CPU 内訳で INTEGRATION は全体の 0.82% にすぎない）。
   実行中のランをこの理由だけで再起動する価値はない
