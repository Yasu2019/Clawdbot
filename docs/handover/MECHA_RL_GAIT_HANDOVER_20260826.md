## 2. 自然歩行の真因（このセッション最大の発見）

### 脚は振れている。着地直前に引き戻している。

v53 の実測（平地 / cmd 0.27 / 128env / DR無 push無）:

    両脚の開き 最大        47.8°
    接地時の両脚の開き     13.6°   <- 開きの7割が着地までに失われる
    一歩の踏み出し幅      0.170 m  (脚長比 0.18、人間 0.78)
    接地時の膝屈曲        11.0°   (ほぼ伸びており律速ではない)
    胴体ピッチ 平均        0.2°    (前傾していない)
    立脚中の足の滑り      0.162 m/s

**最大 47.8° で着地できていれば一歩は `2 × 0.90 × sin(23.9°) = 0.73 m` で人間とほぼ同じ。**
実際の 13.6° での着地が 0.17 m を生んでいる。

既存の報酬項に**「どこに足を着くか」を要求するものが一つも無い**ため、方策は
「振り出してから引き戻す」解に落ち着いている。速度指令は歩数で満たせるので、
これで報酬上は困らない。

### 次の一手（未着手・要 Plan 承認）

接地の瞬間の両脚の開きを直接報酬する、または着地前の引き戻しを罰する項の新設。
新規報酬項なので Plan を出してから着手すること。

| **v53** | **平地専用に切り分け** | — | **ケイデンス・duty が人間値に到達** |

### 効いた理由（v50）

二足歩行RLでは**速度指令が「頻度」でも「歩幅」でも満たせる**。歩幅を要求する項が
弱いと、方策は楽な頻度で満たす。`feet_air_time` は legged_gym が
`# Reward long steps` と明記する標準項だが、当プロジェクトでは scale 2.0 でも
寄与が `alive` の 0.6% しかなく実質無効だった。30.0 で約9%になり機能した。

### corridor のトレードオフ境界

**v50 を超える歩容改善は 4実験すべてで完走率を代償にした**（v46/v49/v51/v52）。
階段踏破に要る「素早く足を置き直す」能力と、人間的 duty factor（長い単脚支持）が
競合する。平地に切り分けた途端に人間値へ到達したことで、**歩容の律速は報酬設計
ではなく地形の同居**だと確定した。

## 4. 評価規約（守らないと誤った結論に到達する）

### DR は既定8グループ。env 数を増やしても再現しない

`_apply_dr` は `num_envs` を `groups`(既定8) に chunk し、グループごとに1回だけ
質量とKPを引く。**2048env でも独立抽選は8回**で、256env が同一値を共有する。

    DR8(既定)+push  完走 6.3/10.9   再現幅 4.6pt
    DR2048+push     完走 7.9/10.3   再現幅 2.4pt
    DR無+push       完走 10.8/10.5  再現幅 0.3pt
    DR無+push無     完走 26.4/26.4  再現幅 0.0pt

**世代間比較は必ず `--no-dr` で行う。** 「2048env以上で比較する」という規約を
一度作ったが誤りで、env 数は効かない。

### 関節使用量は1周期窓の p2p で測る

全区間 max−min はドリフトを含み、「毎歩振っている」のか「20秒でずれた」のかを
区別できない。実例:

    股関節  1周期振幅 16.8°  /  全区間max-min 49.4°
    膝      1周期振幅 25.8°  /  全区間max-min 49.7°

**膝が可動域40°を使い切っている**と誤判断して膝拡大に踏み切ったが、1周期では
25.8°で旧可動域の内側だった。

### レンダは既定で DR 有効。判定するときは `--no-dr`

`render_walk_rsl.py` は DR が既定で有効。**1env = 1回の抽選**なので不運を引くと
完全に失敗する。実例: v53 の同一 ckpt で

    DR有: travel 0.24m  fell=True   min_upright 0.525
    DR無: travel 8.45m  fell=False  min_upright 0.963

診断と条件を揃えないと偽の失敗・偽の成功を掴む。

### 静止フレームでは歩容の自然さを判定できない

静止画で確認できるのは四肢の連結・直立・物理破綻の有無まで。**歩容の自然さは
時間方向の性質**なので、動画として通しで見るか時系列で判定する。
このセッションで「目視確認済み」と書いて自然歩行を主張したのは誤りだった。

### 踏破率を主指標にする

survival は評価窓とコース長の組み合わせでしか意味を持たず、地形をまたいで比較
できない。`eval_course_completion_WIP.py` / `diag_post_climb.py` の踏破率を使う。

## 6. 棄却した仮説（再試行しないこと）

| 仮説 | 棄却の根拠 |
|---|---|
| 参照速度(0.0585)と指令(0.27)の4.6倍不整合が原因 | 指令を0.0585に下げてもケイデンスは321→316でほぼ不変 |
| 足を持ち上げていない | 足クリアランスのピークは25cm。膝角を代理指標にしたのが誤り |
| 膝可動域40°が律速 | 1周期振幅は25.8°で可動域の内側。拡大しても歩幅は0.099→0.100mで不変 |
| `action_rate` が脚振りを抑えている | G1 と完全に同一値(-0.01)。異常ではない |
| `gait_symmetry` が逆位相歩行を罰している | 残差に対する項で、振らない方策ほど罰が大きい「振らせる側」 |
| `pose_prior` が飽和して勾配ゼロ | 実測 exp(-8×0.1006)=0.447 で感度の高い領域。勾配 -3.58 |
| 脚の振りが前進に変換されていない | 0.17m × 1.87歩/秒 = 0.32 m/s が実測速度とほぼ一致 |
| 胴体の前傾で実効振り角が減っている | 胴体ピッチ平均 0.2°。前傾していない |
| `foot_clearance` が階段でマスクされているのが律速 | 平地でもほぼゼロ寄与。マスク免除しても差が出ない |

**幾何からの推論は3連続で外れ、直接測定だけが正しい答えを出した。**
この種の判断は測定を先に行うこと。

## 7. 参照モーションと機体

### 参照ライブラリ（`stage_b/refs/`）

| ファイル | period | clip_vx | 歩幅 | 脚長比 |
|---|---|---|---|---|
| `v50_ref_stairs_up_cmu143_17_armneutral.json` | 1.775s | 0.0585 | 0.104m | 0.11 |
| `v50_ref_stairs_up_cmu83_27.json` | 1.85s | 0.1139 | 0.211m | 0.22 |
| `v50_ref_walk_100style_neutral_fw.json` | 1.3s | 0.331 | 0.430m | 0.46 |
| `v50_ref_stairs_up_cmu143_17_knee65*.json` | 1.775s | 0.0585 | — | 膝-65°用 |

- **v44/v50/v52/v53 が使うのは `cmu143_17_armneutral`**（階段用）
- `armneutral` は**腕の全DOFをゼロ固定**。腕-脚協調が無い直接原因
- `clip_vx_mps` は切り出し位置により 0.038〜0.789 と**20倍変動する**（被験者が
  撮影空間で方向転換するため）。クリップの歩行速度の指標として信用しないこと
- `bvh_retarget.py` の `fit_amplitude` は人間モーションを**機体可動域の80%に圧縮**
  する。どの参照でも関節振幅はほぼ同じになる

### 機体（`artifacts/v50_mecha.xml`）

**2026-08-26 に git 追跡対象に追加した**（それまで `.gitignore` の `*.xml` で
除外されており `git checkout` で戻せなかった）。

    hip    -40〜+40°  (80°)   人間の歩行に必要 50°  足りる
    knee   -30〜+10°  (40°)   必要 62°              半分（現在-30°に戻してある）
    ankle  -20〜+20°  (40°)   必要 30°              足りる

胴体は単一剛体。**骨盤・腰関節・脊椎・hip yaw が無い**（`torso` の free joint 直下に
`upper_leg` と `upper_arm` が直接ぶら下がる）。腕振りが脚の角運動量を打ち消す機能は
胴体の逆回旋なしには成立しないため、腕-脚協調の改善には腰の自由度が要る可能性がある。

膝可動域の拡大は**既存 ckpt を無効化しない**ことを実測で確認済み（学習なしで
v44 をロードして踏破率 43.4%→39.5%、約4ptの劣化のみ）。質量変更とは違い
上位集合への変更のため。ただし v48 で拡大しても歩幅は変わらなかった。
