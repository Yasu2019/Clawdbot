# Codex Master Protocol
Version: 1.1
Purpose: 3Dモデル更新後に、既存資産調査、導入可否判断、詳細設計、DR、実装、テスト、最終報告までを安全に進めるための統括プロトコル
Encoding: UTF-8 with BOM
Filename rule: ASCII only

---

## 1. 目的

本プロトコルの目的は、Dockerコンテナ内の Codex が、既存システムとの整合を保ちながら、
次の機能群を安全に検討・設計・実装するための統一手順を定義することです。

### 1.1 主機能
- ユーザーが更新した 3D モデルを受け取り、後続設計へつなぐ
- 既存アプリや既存コードを探索し、重複実装を避ける
- 類似アプリが存在する場合は、次のいずれかを判断する
  - 一部融合
  - 全部取り込み
  - 既存採用優先
  - 今回は導入保留
  - 新規実装
- 採用が決まった場合は、詳細設計を作成する
- DR を経て、承認後に実装する
- プレス金型案件では、設計結果を kinematics_hub で視覚化する
- 将来の OpenRadioss / OpenFOAM 連携余地を設計へ残す

### 1.2 可視化の方針
プレス金型については、厳密な FEM 計算を必須としません。
重要なのは、ユーザーが以下を直感的に理解できることです。

- 何ステージ構成なのか
- 各ステージでどのような加工が起きるのか
- 製品形状がどのように変化していくのか
- どのパンチ / ダイ / 曲げ / 打ち抜き / 絞りが、どの段階で作用するのか

## 2. 前提環境

本プロトコルは、次のような環境を前提とします。

- Docker ベースの既存開発環境
- 既存 Portal ダッシュボードが存在する可能性
- OpenClaw / Codex / 各種 AI 支援コードが混在している可能性
- 既存の CAD / CAE / 変換 / 可視化 / Portal カードが存在する可能性
- 既存実装の破壊的変更は最小限に抑えること

### 2.1 既存資産衝突の回避
Codex は、実装開始前に必ず既存資産を調査すること。
特に次を優先調査対象とします。

- apps
- portal cards
- viewer
- kinematics
- dxf / step / stl / freecad / cad conversion
- die / mold / stamping / progressive die
- geometry / stage / sequence / animation
- manufacturing / process planning
- scripts / docs / specs / archived prototypes
- OpenRadioss / OpenFOAM / solver integration

## 3. 絶対遵守事項

### 3.1 まず調査、あとで実装
類似アプリ、類似機能、過去の試作、未完成コードを確認する前に
新規実装へ進んではなりません。

### 3.2 破壊的変更の禁止
既存システムを不用意に置換しないこと。
以下の順序で検討すること。

1. 既存利用
2. 一部融合
3. 既存をラップして拡張
4. 新規追加
5. 置換は最後の手段

### 3.3 導入可否の明文化
調査結果から、必ず以下のいずれかを文章で明示すること。

- Adopt: そのまま導入可
- Integrate: 一部融合で導入
- Import and Adapt: 外部 or 既存コード取り込み後に調整
- Hold: 今回は保留
- Reject: 不採用
- New Build: 新規構築

### 3.4 DR 前に実装を本格着手しない
試作的スパイクは許容するが、本実装は DR 後とします。

### 3.5 文字化け防止
Codex が生成・更新するファイルは、原則として以下を守ること。

- 文字コード: UTF-8
- 日本語文書を Windows で配布する場合は UTF-8 with BOM を優先
- ファイル名は英数字、ハイフン、アンダースコア中心
- 機種依存文字を避ける
- Markdown / JSON / YAML / CSV の文字コードを混在させない
- Shift_JIS 保存はユーザー要求時のみ

## 4. 全体フェーズ

### Phase 0: 既存資産調査
目的:
- 似たアプリが既にあるか
- 一部融合で済むか
- 取り込み候補があるか
- 今回は保留したほうがよいか

実施内容:
- リポジトリ全体検索
- docs, apps, scripts, archived code の確認
- 既存 Portal カードの確認
- UI ルートの確認
- 依存関係、重複機能、競合ポート、命名衝突の確認
- 実際に動くか簡易確認

成果物:
- 類似アプリ一覧
- 再利用候補一覧
- コンフリクト一覧
- 推奨方針メモ

### Phase 1: 比較検討と推奨方針決定
比較対象:
- 全面導入
- 一部融合導入
- 既存採用優先
- 保留
- 新規実装

成果物:
- 比較表
- 推奨案
- 採用理由
- 不採用理由

### Phase 2: 詳細設計
成果物:
- 詳細設計書
- データ構造
- UI 方針
- Portal / Compose 影響整理
- 将来 solver 連携ポイント

### Phase 3: DR
成果物:
- DR 確認結果
- 懸念事項
- Go / 条件付き Go / Hold

### Phase 4: 実装
成果物:
- 変更ファイル
- 実装メモ
- ロールバックメモ

### Phase 5: テスト
成果物:
- テスト手順
- テスト結果
- 未確認事項

### Phase 6: 最終報告
成果物:
- 最終報告書
- 将来拡張案
- 再開条件または次アクション
