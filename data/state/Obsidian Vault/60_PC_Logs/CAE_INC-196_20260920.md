# CAE INC-196 -- Elmer output discovery and weld-front initialization

## Goal

任意3D樹脂CAEで、実solver成功をHOLDと誤判定せず、同時初期充填をウエルドラインと誤表示しない。

## Context

- Date: 2026-09-20 JST
- Host: K10 / Windows / Docker Desktop 29.7.2
- Repository: `D:/Clawdbot_Docker_20260125`
- Solvers: CalculiX 2.16, Elmer 8.4
- Material: virtual; `UNCALIBRATED_SCREENING`
- Running OpenFOAM/tri-track/DXF2STEP processes were not stopped or reused.

## Observed facts

1. ElmerSolver returned 0 and printed its finish marker.
2. `Mesh DB "." "mesh"` caused `mesh/case.result` and `mesh/shrinkage0001.vtu`; the first verifier searched only the case root.
3. The VTU stores displaced coordinates in this Elmer image. Original coordinates are recovered as `x_original=x_vtu-u`.
4. The first weld detector allowed predecessor lag zero, so an initial filled blob could geometrically surround a cell and resemble two colliding fronts.

## Hypotheses

- H1: recursive artifact discovery plus parsing and SHA binding prevents directory-layout false HOLD without weakening the solver gate.
- H2: a transported predecessor must arrive strictly earlier than the target; rejecting equal arrival separates initialization from a moving front.

## Decision rule

- IF Elmer exits 0 but expected root outputs are absent THEN search only under the immutable case directory, require one result and one parseable VTU, and record relative path/SHA BECAUSE `Mesh DB` controls the output subdirectory.
- IF source arrival time is not strictly earlier than target arrival time THEN it is not a predecessor BECAUSE equal-time cells can belong to the initial condition rather than two merging fronts.
- IF output is a field-derived weld candidate THEN retain `UNCALIBRATED` and `strength_prediction=false` BECAUSE collision location is not weld strength.

## Procedure

1. Generate a one-tetra Elmer native mesh and thermoelastic SIF.
2. Run `eperera/elmerfem:latest` in an ephemeral container.
3. Preserve log, result, VTU, return code, finish/fatal markers, relative paths, and SHA256.
4. Parse temperature/displacement; evaluate both original and deformed VTU coordinate conventions.
5. Compare `u=alpha*(T-Tref)*x` with the solved field.
6. For weld candidates, interpolate alpha first arrival, require positive predecessor lag, compare incoming directions and arrival-time difference, and accumulate a persistent union map.
7. Run negative controls for a one-way chain and a simultaneous initial gate blob.

## Failure signatures

- `HOLD_SOLVER_OR_OUTPUT_FAILED` with return code 0 and finish marker: likely output search path mismatch.
- Candidate at `t=0` inside an initially filled inlet blob: equal-time predecessor acceptance.
- VTU coordinate mismatch approximately equal to displacement: ResultOutput wrote deformed coordinates.
