# 3D生成ワークフロー探索でリポジトリ全体検索がタイムアウト

- 日時: 2026-07-30 JST
- Beads: `Clawdbot_Docker_20260125-hc0l`
- コマンド: Hunyuan prompt ID / checkpoint名をプロジェクトルートから `rg` 検索
- 結果: 30秒上限を超過し exit code 124。3D生成は未開始。

## 観測事実

- 既知のComfyUI出力、checkpoint、生成済みGLB、入力画像は確認済み。
- 検索は `.git`、`node_modules`、一部モデル拡張子を除外したが、巨大な生成物・データ領域を十分に除外していなかった。
- 2026-07-28の事前検査OOMでは「既知ディレクトリに限定する」が対策として記録済みだった。
- 今回はOOMではなく、明示した30秒タイムアウトで停止した。
- 検索子プロセスはタイムアウト終了し、GPU生成プロセスは起動していない。

## 5 Why

1. なぜ検索がタイムアウトしたか: ルート全体を走査した。
2. なぜ走査量が大きかったか: 巨大な生成物・データディレクトリが多数ある。
3. なぜ既知パスだけに限定しなかったか: prompt IDが別場所に保存されている可能性を優先した。
4. なぜその判断が不適切か: 既知のComfyUIディレクトリ、ログ、status JSONを先に調べれば十分だった。
5. なぜ再発と判断するか: 2026-07-28に同種の広域列挙を禁止する対策を既に定めていた。

## Fishbone / FTA

- Method: 検索起点が広すぎた。
- Repository: 大規模な生成物・モデル・外部データを含む。
- Control: タイムアウトは機能し、無制限走査は防止した。
- Memory: 過去の「狭い検索」ルールを実行判断に十分反映できなかった。
- Top event: 3D生成準備が進まない。
  - AND: ルート検索
  - AND: 除外不足
  - AND: 既知パス優先ルール不履行

## 対策実施計画（ユーザー確認待ち）

1. 検索対象を以下だけに限定する。
   - `vnccs_comfyui_clawstack_pro/ComfyUI_app/user`
   - `vnccs_comfyui_clawstack_pro/ComfyUI_app/temp`
   - `vnccs_comfyui_clawstack_pro/ComfyUI_app/output/3d`
   - `logs`
   - ルートの `harness_status_hunyuan3d_*.json`
2. ComfyUIが起動済みなら `/history/{prompt_id}` をローカルHTTPで照会する。
3. 履歴が無ければ、既存GLBを基準として改善ルートを選び、広域検索を繰り返さない。
4. 各生成試行に固有ディレクトリとstatus JSONを作り、GPU・進捗を監視する。
5. 静止画、代表モーションフレーム、動画を目視し、不合格なら原因を一つずつ変えて再試行する。

## 回復・ロールバック

- 変更された3D資産はない。
- 検索はタイムアウト終了済みで、残留生成プロセスはない。
- 次回はallowlistパスだけを使用する。
