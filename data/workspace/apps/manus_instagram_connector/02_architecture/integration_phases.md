# 統合フェーズ設計

## Phase 0: 読み取り専用監査

目的: 既存環境を壊さず把握する。

実施内容:

- docker ps
- docker compose config の確認
- .envの存在確認。ただし中身は表示しない
- Portal構成ファイルの候補探索
- 既存データディレクトリの有無確認
- Python/Node/Dockerのバージョン確認

完了条件:

- 既存サービス・ポート・volume一覧が取得できた
- 破壊的コマンドを実行していない
- 統合候補と競合候補が整理された

## Phase 1: オフライン運用

目的: Instagram連携なしで投稿案生成とレビューだけ行う。

実施内容:

- 投稿カレンダーCSVを作る
- 投稿文チェックを行う
- NG表現を検出する
- 人間承認フローを回す

完了条件:

- 10件以上の投稿案が作成できる
- NGチェックが動く
- 人間承認の記録が残る

## Phase 2: Manus手動連携

目的: Manusを使うが、投稿は手動確認。

実施内容:

- Manusに競合分析依頼
- Manusに投稿案生成依頼
- 結果をOpenClaw側テンプレに貼る
- 人間が確認

完了条件:

- 投稿案品質が基準を満たす
- 誤情報率が許容範囲
- 画像・動画の著作権リスクを判断できる

## Phase 3: Manus Instagram Connector連携

目的: 正規ConnectorでInstagramプロアカウントを接続。

実施内容:

- Instagram Professional Account確認
- Connector権限確認
- テスト投稿は非公開/限定的な検証用で実施
- 投稿前レビューを必須化

完了条件:

- 承認済み投稿のみ実行される
- 投稿ログが残る
- インサイト取得ができる

## Phase 4: 週次改善サイクル

目的: 分析→改善のループを作る。

実施内容:

- 週次レポート
- 保存率・プロフィール遷移・リンククリック確認
- 次週投稿案更新
- note/テンプレ販売導線改善

完了条件:

- 投稿工数が削減
- KPI推移が見える
- 危険な自動化が発生していない

## Phase 5: 本格運用判断

Claudeが以下を判定。

- 継続
- 縮小
- 中止
- ジャンル変更
- 有料プラン検討
- OpenClaw内製化検討
