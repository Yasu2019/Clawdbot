# 外観検査・寸法測定AI ローカル自律開発プロトコル v1.0

## 1. 目的

本プロジェクトは、金属プレス部品、プラスチック射出成形部品、リード線・端子、半田付け部を対象に、外観不良検出と画像寸法測定を行うローカルシステムを構築する。

目標は「AIが勝手に本番モデルを変更する完全自動学習」ではない。ユーザーが確定した判定を安全に蓄積し、候補モデルをGPUで作成し、固定評価・シャドー運用・人承認を経て改善する、人間参加型の継続学習システムとする。

## 2. 最優先原則

1. 通常運用は追加費用ゼロのローカル構成とする。
2. 製品画像、顧客情報、社内ノウハウを外部APIへ自動送信しない。
3. 本番検査を学習より優先し、GPU競合時は学習を停止する。
4. 新しいモデルを自動的に本番へ昇格しない。
5. 過去モデル、レシピ、判定履歴へロールバックできる。
6. 寸法の表示桁と測定精度を混同しない。
7. 0.001 mm精度は、光学・治具・校正・環境・MSAで実証されるまで保証しない。
8. 公開画像は、出典・ライセンス・商用利用可否を確認してから使用する。

## 3. 対象不良

### 金属プレス

傷、打痕、圧痕、バリ、欠け、割れ、変形、曲げ不足、曲げ過多、穴位置、穴径、汚れ、油、シミ、酸化、異物、部品違い。

### 樹脂成形

ショートショット、バリ、ヒケ、ボイド、ウェルド、焼け、黒点、白化、クラック、反り、色むら、異物、ゲート残り、欠け。

### リード線・端子

被覆むけ長さ、芯線露出、芯線切れ、素線飛び出し、端子変形、圧着位置、圧着不足・過多、線色、組付け、傷、汚れ。

### 半田

不足、過多、ブリッジ、未半田、濡れ不良、ボイド疑い、半田ボール、ピンずれ、異物、焼け、クラック疑い。

不良モードはコードへ固定せず、製品レシピまたはマスタに登録し、重大度、限度見本、検査方法、改訂履歴を保持する。

## 4. 二系統設計

### 高速外観検査

広視野の画像から異常を検出し、位置、分類候補、信頼度を出力する。撮影、転送、前処理、推論、後処理、保存を個別に計測し、p50、p95、最大値を記録する。目標p95 100 msは実機で検証する。

### 精密寸法測定

外形、幅、高さ、穴径、穴間、角度、R、端子位置、被覆むけ長さ等を測る。可能な限りOpenCV等の決定論的な幾何処理を用い、LLMに寸法値を推測させない。

広視野と1 µm精度が両立しない場合は、全体カメラと精密カメラの二眼、疑わしい領域の再撮影、電動ステージ、専用治具、別工程化を検討する。

## 5. 検査アルゴリズム

- 画像品質：ぼけ、明るさ、白飛び、黒つぶれ、位置ずれ。
- ルール処理：エッジ、輪郭、円・直線フィット、テンプレート、色差、形態学処理。
- 教師あり学習：既知不良の分類、検出、セグメンテーション。
- 異常検出：良品中心のPatchCore、EfficientAD、FastFlow等を比較。
- 判定統合：品質、異常スコア、既知不良、寸法、モデル間不一致、製品ルールを統合。

判定はOK、NG、REVIEWを基本とし、撮影異常、製品未登録、判定不能、システム異常を追加できる。

## 6. REVIEW

次をREVIEWへ送る。

- しきい値付近。
- モデル間で不一致。
- 未知の異常だが不良名称を特定できない。
- 画像品質が基準外。
- 寸法エッジが不安定。
- 過去分布から大きく外れる。
- ChampionとChallengerの判定が異なる。

元画像、マーキング画像、製品、ロット、設備、レシピ、モデル版、スコア、寸法、理由、ユーザー判定、コメント、判定者、学習使用可否を保存する。

## 7. GPU自律学習

RTX GPUは推論、特徴抽出、Challenger学習、評価に使用する。本番推論を最優先し、CPU使用率、GPU使用率、空きVRAM、温度を確認してアイドル時だけ学習する。再起動やCUDA障害に備え、チェックポイントとCPU縮退を用意する。

学習開始条件は、確定済みデータの増加、新製品、新不良モード、誤判定増加、撮影条件変更、性能低下、ユーザー指示とする。同じデータを時間だけを理由に繰り返し学習しない。

## 8. Champion / Challenger

1. ユーザー確定データを収集。
2. 重複、破損、ラベル矛盾、ロット偏りを確認。
3. 学習、検証、固定テストを分離。
4. Challengerを作成。
5. Championと同じ固定データで比較。
6. 重大不良別の見逃し、誤検出、再現率、F1、速度、資源使用量を確認。
7. シャドー運用。
8. ユーザーが承認した場合のみ昇格。
9. 旧ChampionをArchiveへ保存。
10. 問題時にロールバック。

合格したChallengerも自動昇格しない。

## 9. 公開データ

AIは公開データセット候補を検索・整理できるが、無差別ダウンロードや画像検索結果の無断学習を行わない。

外部データはAPPROVED、RESEARCH_ONLY、PENDING、REJECTEDに分ける。APPROVEDには、公式配布元、明確なライセンス、商用利用可、ユーザー承認、SHA-256一致が必要である。

学習優先順位は、実設備のユーザー確定画像、限度見本、同材質社内データ、商用利用可能公開データ、承認済み合成データ、研究限定データの順とする。研究限定データを本番モデルへ混入させない。

## 10. 無料ソフトウェア構成

Python、OpenCV、PyTorch、ONNX Runtime、OpenVINO、Anomalib、FastAPI、SQLite/PostgreSQL、CVAT Community、Ollama、OpenCode、Gitを候補とする。

ライブラリ本体、依存関係、学習済み重み、データセットのライセンスを個別に管理する。外部有料APIは初期状態で無効化する。

## 11. 開発エージェント

- Planner：タスク分割、完了条件、リスク。
- Implementer：コード、設定、UI。
- Reviewer：設計、安全、ライセンス、破壊的変更。
- Test Agent：単体、結合、回帰、性能、異常系。
- Vision Evaluation Agent：見逃し、誤検出、撮影条件分析。
- Documentation Agent：README、操作、復旧、引継ぎ。

同一AIだけで実装と最終承認を完結させない。

## 12. Fable5監査Gate

- Gate 1：要求定義。
- Gate 2：基本設計。
- Gate 3：1製品・1面・少数不良のPoC。
- Gate 4：REVIEWと継続学習。
- Gate 5：速度・GPU/CPU負荷。
- Gate 6：現場試験前。
- Gate 7：本番候補。

Fable5へは全履歴ではなく、変更目的、差分、テスト、精度・速度、失敗例、残課題、判断依頼、ロールバックをまとめた監査パケットを渡す。

## 13. 初期PoC

金属プレス部品1種類、1面、傷・打痕・バリ等、穴径または外形1項目、OK/NG/REVIEW、マーキング、履歴、ユーザー修正、Challenger比較を実装する。成功後に樹脂、リード線、半田へ展開する。

## 14. 本番前の完了条件

- 新製品・新不良をレシピで追加できる。
- 不良位置と集計を出力できる。
- REVIEWを人が確定できる。
- Champion/Challenger比較とロールバックができる。
- 外部APIなしで稼働できる。
- GPU障害時に縮退できる。
- MSAで寸法能力を説明できる。
- 処理時間を工程別に記録できる。
- 操作・判定・変更を追跡できる。
- 別のAIまたは人へ引き継げる。
