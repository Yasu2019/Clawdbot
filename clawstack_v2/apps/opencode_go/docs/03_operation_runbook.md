# 03 運用Runbook

## 毎回の調査フロー
1. 調査テーマを決める
2. 公開情報のみ取得
3. 取得情報を要約
4. 出典・日付・信頼性を記録
5. 有益性スコアリング
6. リスク判定
7. 採用候補レポートを作る
8. 変更案は `proposal/` に保存
9. GitHubバックアップ
10. 人間承認後に適用

## 採用してよい例
- Portalに新カードを追加するだけ
- LiteLLMに外部モデル候補を追加するだけ
- n8nに手動実行ワークフローを追加するだけ
- レポートテンプレートを追加するだけ

## 慎重に扱う例
- Docker Compose変更
- DBスキーマ変更
- 既存Portal UI全面変更
- 既存RAGパイプライン変更

## 禁止例
- 機密データを外部AIへ送る
- 自動で本番composeを変更
- ボリューム削除コマンド
- 認証情報の平文コミット
