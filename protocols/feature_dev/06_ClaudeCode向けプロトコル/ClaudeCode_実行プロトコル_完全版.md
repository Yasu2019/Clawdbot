# Claude Code 向け実行プロトコル（完全版）

以下を Claude Code にそのまま貼る運用を想定しています。
案件ごとに `目的` 以下だけ差し替えてください。

```text
/feature-dev
目的:
- ここに今回やりたい機能追加または改修内容を書く

背景:
- 現状の業務課題
- 現在の運用
- なぜ今必要か
- 誰が使うか

対象:
- リポジトリ:
- 対象ディレクトリ:
- 主対象ファイル:
- 関連ファイル:
- 関連データソース:

最重要制約:
- 既存仕様を極力維持すること
- 変更範囲は必要最小限にすること
- 既存実装を先に十分に探索すること
- DB を使う場合は READ ONLY を厳守すること
- INSERT / UPDATE / DELETE / MERGE / DROP / ALTER / TRUNCATE を禁止
- 既存 Docker / Compose / Portal 構成と競合しないこと
- ポート競合がないこと
- 機密情報や鍵をコードに埋め込まないこと
- エラーハンドリングを入れること
- Windows 環境でも扱いやすい文字コード・手順にすること

進め方:
1. Explorer として既存コード、依存関係、影響範囲を調査
2. Architect として最低 3 案を提示
   - 最小変更案
   - 実用バランス案
   - 拡張性重視案
3. 各案の長所短所、変更量、影響範囲、テスト容易性を比較
4. 今回の目的に最も合う採用案を 1 つ選び、その理由を明示
5. 採用案のみを実装
6. Reviewer として不具合、仕様漏れ、命名、例外処理、テスト不足を確認
7. 根拠の薄い指摘は除外し、重要度順に報告
8. 最後にまとめを作成

必須出力:
- 現状調査結果
- 案比較表
- 採用案と採用理由
- 変更ファイル一覧
- 実装内容要約
- テスト項目
- リスク
- ロールバック方法
- 未解決課題
- 現場向けの短い説明

レビュー観点:
- QA / IATF 的に説明可能か
- 出力値の根拠が追跡可能か
- 現場担当者が扱えるか
- 既存機能を壊していないか
- エラー時に安全停止できるか

禁止事項:
- 本番DBや外部システムへの書き込み
- 無関係なコード整理の抱き合わせ
- 根拠のない大改修
- 既存帳票の列順や意味の無断変更
```
