# Portal / Docker 統合向けテンプレ

```text
/feature-dev
目的:
- 既存の Portal または Docker Compose 環境に、新しい業務機能を安全に統合する

背景:
- 既存環境には複数のカード、サービス、MCP、RAG が存在する
- 重複実装、ポート競合、役割重複を避けたい
- 部分導入か全面導入かを整理したい

対象:
- Portal カード
- nginx 配下の静的アプリ
- docker compose
- バックエンド API
- 監視・ログ導線

制約:
- 既存カードと重複する場合は統合優先
- ポート競合禁止
- loopback bind を優先
- compose 変更は最小限
- 監視導線を壊さない
- 実装前に「全面採用 / 部分採用 / 保留」を判定する

出力物:
- 現状調査
- 競合判定
- 統合案比較
- 採用方針
- 変更ファイル一覧
- 起動確認手順
- ロールバック手順

受入条件:
- 既存カードと役割衝突しない
- 起動確認が取れる
- ログ確認箇所が明確
- 再起動手順が明記されている
```
