# OpenClaw 接続方針

## 1. 前提
OpenClaw から直接 Foundry に全面接続せず、まずは LiteLLM 経由に統一する。

理由:
- 接続先の抽象化
- 切替容易性
- ロールバック容易性
- ログ観測の簡素化

## 2. 推奨
OpenClaw → LiteLLM → Ollama / Foundry

## 3. ルール
- 既定モデルは当面 Ollama
- 比較時のみ Foundry alias を指定
- OpenClaw の本番プロンプトや既存動作は最小変更
- 変更履歴を残す

## 4. 比較に向く OpenClaw タスク
- 短い社内メール下書き
- 文書要約
- 手順整理
- コード断片の修正
- QAチェック項目整理

## 5. 比較に不向きな初期タスク
- 重要な本番自動化
- 既存顧客向け自動返信
- 監視・通知の中核フロー
- 既に安定している本番タスク

## 6. 目標
OpenClaw 側の差分は最小にし、判断材料だけ増やす。
