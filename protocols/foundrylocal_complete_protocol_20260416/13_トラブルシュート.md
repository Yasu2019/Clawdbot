# トラブルシュート

## 1. Foundry 側が応答しない
確認:
- 起動できているか
- ポート競合がないか
- エンドポイント URL が正しいか
- OpenAI互換 path が一致しているか

対応:
- まず単体で curl / 簡易クライアントから叩く
- LiteLLM 経由の前に直結で確認する

## 2. LiteLLM でエラー
確認:
- model 名の指定
- api_base
- 認証の要否
- リクエスト形式の差異

対応:
- 既存 Ollama alias と比較する
- Foundry alias を一旦最小構成にする

## 3. OpenClaw で挙動が不安定
確認:
- OpenClaw 直結ではなく LiteLLM 経由か
- 比較用 alias を誤って default にしていないか
- タイムアウトが短すぎないか

対応:
- まず Ollama に戻す
- その後 Foundry 単体テストへ切り分ける

## 4. n8n で処理が乱れる
確認:
- 本番フローを触っていないか
- 比較フローが別保存されているか
- 失敗時の通知先が本番に繋がっていないか

対応:
- 比較フローを停止
- 本番フローへの影響を切る

## 5. メリットが見えない
判断:
- それは正常な結論
- 無理に採用しない
- 「現時点保留」は十分に合理的

## 6. Qwen 主系を崩したくない
推奨:
- 崩さない
- Foundry は将来候補として横に置くだけ
- 実利が出るまで評価対象に留める
