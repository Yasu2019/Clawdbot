# 完全版 実装方針

作成日: 2026-04-16

## 1. 結論
最も安全で合理的な方針は、以下です。

- 主系: Ollama
- 比較系: Foundry Local
- ルータ: LiteLLM
- エージェント: OpenClaw
- ワークフロー: n8n
- 判断: 明確な利点が出た場合のみ採用強化。薄ければ保留。

## 2. なぜ全面移行しないか
Foundry Local は魅力がある一方、現時点では次の不確実性があります。

- 既存主力モデル（特に Qwen 系）との相性・扱いやすさ
- 現環境への追加保守コスト
- 体感速度差が本当に出るか
- OpenClaw や LiteLLM 接続時の細部調整
- 既存 Docker / Windows / WSL 構成への影響

したがって、最初から「置換」は危険です。

## 3. 基本アーキテクチャ
```text
OpenClaw
  ↓
LiteLLM
  ├─ local_primary_ollama   → 既存主系
  └─ local_compare_foundry  → 新規比較系
```

## 4. 導入原則
1. 既存 Ollama は止めない
2. 既存 alias は変えない
3. Foundry Local は新規 alias として追加
4. 比較結果が出るまで default は Ollama のまま
5. ロールバックは 5 分以内を目標に設計
6. 比較用ログを残す
7. 本番経路に混ぜる前に単体疎通確認を行う

## 5. 役割分担案
### 案A（最保守）
- Ollama: 全業務
- Foundry: ベンチマークのみ

### 案B（現実的）
- Ollama: 日常業務・Qwen 主系
- Foundry: API 組み込み比較、軽量モデル比較、将来の配布前提テスト

### 案C（将来）
- 開発: Ollama
- 製品組み込み・配布: Foundry
- ただし、Go 判定後のみ

## 6. 鈴木様向け推奨判断
現段階では「併用評価」が最も妥当です。
明確な差が無いなら、堂々と保留で問題ありません。
