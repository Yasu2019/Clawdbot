# QA_UI_AUDIT_SKILL v1.0

## 目的
既存または生成された UI を、見た目の好みではなく
**業務適合性・判断速度・誤操作防止・保守性** の観点で監査する。

---

## 監査手順
対象 UI を見たら、以下の順に評価すること。

### 1. 主目的確認
- この画面の主目的は 1 文で説明できるか
- 目的が複数混在していないか
- 誰が何のために使う画面か明確か

### 2. 判断速度
- 3 秒以内に正常 / 注意 / 異常が分かるか
- 優先順位の高い情報が先に見えるか
- ユーザーが次アクションを迷わないか

### 3. 情報の過不足
- 判断に必要な数値が欠けていないか
- 説明が多いのに結論が見えない状態ではないか
- 単位 / 更新時刻 / 判定基準が欠落していないか

### 4. 階層構造
- 見出し → 要約 → 詳細 の順になっているか
- 重要度の違う情報が同じ強さで並んでいないか
- 余白・線・タイポグラフィで整理されているか

### 5. 誤操作リスク
- 危険操作が通常操作の近くにありすぎないか
- ボタン名が曖昧でないか
- 承認・取消・削除が視覚的に区別されているか

### 6. 状態表現
- 正常 / 注意 / 異常 / 未測定 / 未承認 / 保留 が識別できるか
- 色だけに依存していないか
- 状態変化の理由が分かるか

### 7. テーブル・グラフ妥当性
- テーブル列順は業務優先度に沿っているか
- グラフは何を比較するか明確か
- 「見栄えのためのグラフ」になっていないか

### 8. 現場適合性
- タッチ操作や大きめクリック領域を考慮しているか
- 手袋・現場端末・高齢者利用でも読めるか
- 長文を読ませすぎていないか

### 9. 実装品質
- TODO / FIXME / placeholder が残っていないか
- ダミーデータ前提で逃げていないか
- コンポーネント分割の意味があるか

### 10. 保守性
- 命名が説明的か
- 画面構成に再利用可能性があるか
- 状態管理や表示ロジックが複雑すぎないか

---

## 出力形式
監査結果は必ず以下形式で返すこと。

### A. 総評
- 1〜3段落で全体所見

### B. 良い点
- 3〜7項目

### C. 問題点
- 重要度順に列挙
- 重大 / 中 / 軽微 を付与

### D. 修正提案
- 具体的に何をどこへどう変えるか記載
- 曖昧表現禁止

### E. 再実装指示
- 必要な場合のみ
- コンポーネント単位で提示

---

## 厳守事項
- 「好み」を監査理由にしない
- 装飾性より業務妥当性を優先
- できるだけ修正可能な形で指摘する
- 可能なら修正版コードまで出す
