# QA_UI_TASTE_SKILL v1.0

## 目的
品質・製造・監査・社内ダッシュボード用途において、
派手さよりも **判断速度・視認性・再現性・保守性** を優先する。

---

## Core Dial

### Design Variance: 3 / 10
- 原則は整列・グリッド基調
- 意味のない非対称は禁止
- レイアウトは説明可能であること
- カードの並び順に業務上の意味を持たせること

### Motion Intensity: 1 / 10
- アニメーションは最小限
- ホバーは色変化・影・罫線程度
- スクロール連動や過剰な演出は禁止
- 数値監視 UI では動きより安定表示を優先

### Visual Density: 8 / 10
- 余白は必要十分
- 情報を薄く広く見せない
- 現場判断に必要な数値を1画面で把握できること
- ただし過密すぎる場合はグルーピングで分割

---

## Visual Principles

### 1. Judgment First
UI は「美しさ」より先に「判断」を助けること。
ユーザーが 3 秒以内に以下を理解できること。
- 正常か異常か
- どこを見るべきか
- 次に何をすべきか

### 2. Numbers Before Decoration
- 主要 KPI は文字説明より数値を前面に出す
- 単位を必ず表示する（mm, %, MPa, pcs, sec, shot など）
- 小数桁数は業務文脈に合わせ統一する

### 3. Explicit State
状態は曖昧にしない。
- 正常
- 注意
- 異常
- 未測定
- 未承認
- 保留

を視覚的に区別すること。

### 4. Explainable Layout
「なぜその位置にあるか」を説明できること。
- 左：条件 / 入力
- 中央：主結果 / 比較
- 右：警告 / コメント / 対応
- 上：サマリ
- 下：詳細 / 履歴 / 根拠

---

## Color Rule
- 装飾目的のグラデーションは禁止
- 状態色は限定使用
  - 正常：緑系
  - 注意：黄 / 橙系
  - 異常：赤系
  - 情報：青 / 灰系
- 背景は高コントラスト過ぎず、数値が読めること
- 「色だけ」で状態を表現しない。必ずアイコン・ラベルも併用

---

## Typography Rule
- 見出し階層を明確にする
- 数値は比較しやすいよう視認性を優先
- 長文説明は必要最小限に抑える
- 重要項目は太字と余白で区別する
- 1つの画面に使う文字サイズの種類を増やしすぎない

---

## Component Rule
- カードは「意味単位」で分ける
- テーブルは横スクロール前提に逃げず、列優先順位を明示
- グラフは必ず「何を比較するか」を先に定義
- KPI カードには以下を推奨
  - 現在値
  - 目標値
  - 差分
  - 判定
  - 更新時刻
- フィルタは画面上部または左側に集約

---

## Dashboard Rule
- 1画面に主目的を1つ置く
- グラフを置くなら「読んだ後に何を判断するか」を明示
- 異常や未承認は上部に優先表示
- 重要なアラートは折りたたみの奥に隠さない

---

## Form Rule
- 必須項目は明示
- 既定値は危険でなければ設定
- 危険操作は確認付き
- 保存 / 承認 / 取消 の区別を明確に
- エラーメッセージは原因と修正方法を示す

---

## Forbidden
- TODO コメントの残置
- 仮実装プレースホルダー
- 「いい感じに」「適当に」など曖昧指示への依存
- 意味のないアイコン多用
- 装飾だけのチャート
- 根拠のない配色
- クリック先が不明な UI
- 余白だけ多いが情報が薄い画面

---

## Required Output Behavior
生成時は次を満たすこと。
1. 画面の主目的を先に定義
2. ユーザーの判断タスクを列挙
3. その判断を最短で支援するレイアウトにする
4. 実装可能な UI を出す
5. ダミー逃げをしない

---

## 適用対象
- 品質ダッシュボード
- 工程監視画面
- 不良分析画面
- IATF 関連 UI
- 検査記録 UI
- Portal カード
