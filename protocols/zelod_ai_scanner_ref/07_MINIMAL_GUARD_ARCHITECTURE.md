# 最小ガードアーキテクチャ案

## 目的
LLM そのものに全責任を負わせず、システム側で防御層を設ける。

## 推奨フロー
1. Input Guard
   - 危険語句
   - 既知の注入パターン
   - 異常な長文 / エンコード崩し
2. Prompt Builder
   - システム指示とユーザー入力を明確分離
   - 監査用に最終プロンプトを保存（必要に応じてマスク）
3. LLM Runtime
   - モデル権限を限定
   - 高リスクモデルと低リスクモデルを分離
4. Output Guard
   - 機密語
   - 内部パス
   - トークン様文字列
   - 管理命令露出
5. Tool Policy
   - toolごとに allow / deny / approval / dry-run を定義
6. Audit / Observe
   - 試験ID
   - 入出力ハッシュ
   - 検知ルールID
   - モデル名
   - tool使用履歴
   - 最終判定

## 最低限の禁止事項
- 何でも実行できる汎用ツールを素通ししない
- RAG の検索結果を無加工で外部出力しない
- エラー時に内部詳細を全表示しない
